Alert doc

Mensagem de feedback contextual e persistente exibida dentro do conteúdo da página. Quatro tons (info · sucesso · aviso · perigo) compartilham a mesma escala de ícone e cor do sistema. Compõe com Toast quando a mensagem é temporária.

1 · Uso

Use o Alert para mensagens que ficam na tela enquanto o estado persiste — uma integração desconectada, um formulário com erro, um plano próximo do limite. Diferente do Toast, ele não some automaticamente.

Quando usar

  • Info — nova funcionalidade disponível, aviso de manutenção.
  • Sucesso — confirmação de ação concluída que deve permanecer visível.
  • Aviso — limite de cota se aproximando, e-mail não confirmado.
  • Perigo — falha que impede a continuação da tarefa.
✓ Faça

Use Alert para feedback contextual fixo — erro de formulário, status de integração, status de conta.

✕ Evite

Substituir o Alert por Toast quando a mensagem deve persistir; o usuário pode não ver o Toast a tempo.

Composição com outros componentes

  • Link dentro do texto para "Saiba mais" ou "Ver detalhes".
  • Button via prop action para CTA primário.
  • ProgressBar abaixo para indicar cota ou limite.

2 · Formatação

Largura de bloco (100% do container). Ícone Phosphor à esquerda, alinhado ao topo do texto. Botão ✕ opcional à direita quando dismissible.

<Alert
  tone="warning"
  title="Verifique seu e-mail"
  action="Reenviar"
  onAction={resend}
  dismissible
  onClose={dismiss}
>
  Confirme para liberar notificações.
</Alert>

3 · Guia de conteúdo

  • Título: curto e descritivo. "Conexão perdida", não "Erro 503".
  • Corpo: opcional — use só quando o título não é autoexplicativo.
  • CTA: verbo de ação. "Reconectar", "Ver detalhes", "Confirmar e-mail".
  • Tom perigo: factual, sem alarmismo. "Não foi possível salvar" > "ERRO CRÍTICO".
  • Evite código de erro no título — coloque-o no corpo se necessário.

4 · Guia de design

Tokens. Fundo e borda derivados do tom: --ob-*-100 e color-mix(--ob-* 28%). Ícone na cor forte do tom. CTA em --ob-*-700.

Posicionamento. Sempre dentro do fluxo da página — nunca flutuante. Se estiver numa seção específica (ex: formulário), posicione logo acima do botão de submit.

Alert vs Toast: Alert fica — Toast vai embora. Se o usuário precisa ver e agir, use Alert. Se é só confirmação de que algo aconteceu, use Toast.
