Toast doc

Notificação flutuante e efêmera que confirma ações ou informa eventos em segundo plano. Aparece na borda inferior-direita e some após ~4,5 s. Compõe com Alert — use Alert quando a mensagem deve persistir.

1 · Uso

Use o Toast para confirmar ações concluídas com sucesso ou notificar eventos assíncronos (sync finalizado, deploy concluído). Ele não bloqueia o usuário e some sozinho.

Quando usar

  • Sucesso — "Tarefa concluída", "Arquivo salvo", "Publicado".
  • Info — evento em background: "Sincronizando com Spotify…".
  • Aviso — condição que o usuário deve notar mas que não bloqueia.
  • Perigo — falha que aconteceu, com opção de retry.
Faça

Empilhe toasts cronologicamente. Limit de 3 simultâneos — remova o mais antigo ao exceder.

Evite

Toast para erros que bloqueiam o fluxo — o usuário pode não ver antes de ele sumir. Use Alert.

Composição com outros componentes

  • CTA inline via prop action: "Desfazer", "Ver", "Tentar de novo".
  • ProgressBar estreita (size sm) dentro do toast para uploads curtos.

2 · Formatação

Largura fixa de 360px. Borda esquerda colorida (3px) como acento do tom. Stacking vertical com gap de 10px, ancoragem top-right (24px das bordas superior e direita). Em mobile (<600px), ancoragem bottom-center com 16px das bordas.

<Toast
  tone="success"
  title="Deploy concluído"
  body="Build #482 está no ar."
  action="Ver log"
  onAction={openLog}
  onClose={dismiss}
/>

3 · Guia de conteúdo

  • Título: confirmação no passado. "Tarefa concluída", "Publicado", "Removido".
  • Corpo: opcional, detalhe do que aconteceu. Máximo 2 linhas.
  • CTA de desfazer: "Desfazer" — só disponível por 4 s (antes do auto-dismiss).
  • Sem ponto final no título de uma linha.
  • Voz Onblide: confirmação direta e positiva. Evite passiva: "O arquivo foi salvo" → "Arquivo salvo".

4 · Guia de design

Tokens. Fundo --ob-surface, borda --ob-border, borda esquerda colorida (3px) como acento do tom. Sombra --ob-shadow-lg.

Ícone. Tamanho 20px quando há body ou action, 18px quando há só título. Alinhado ao topo do conteúdo (align-self: flex-start + margin-top: 1px óptico) — nunca centralizado verticalmente.

Motion. Entrada: translateX(20px) → translateX(0) + fade, 220ms cubic-bezier(0.16,1,0.3,1) (ease-out limpo, sem bounce). Saída: translateX(0) → translateX(20px) + fade, 180ms ease-in. Desliza da direita — direção corresponde à âncora top-right. Hover pausa o timer de auto-dismiss.

Mobile. Em viewports <600px, ancoragem muda para bottom-center (16px das bordas) — evita conflito com teclado virtual e garante legibilidade.

5 · Toast vs Modal de diálogo

A escolha errada entre os dois cria fricção ou deixa o usuário sem contexto. Use esta tabela como guia de decisão.

CritérioToastModal
Requer ação do usuário?Não — some automaticamenteSim — requer confirmação ou input
Ação irreversível / destrutiva?Não (ou já há "Desfazer")Sim — deletar, publicar, pagar
Interrompe o fluxo?Não — usuário continua trabalhandoSim — bloqueia o fundo
Quem iniciou?Confirmação de ação já concluídaConfirmação antes de executar
Volume de conteúdoTítulo + máximo 2 linhasPode ter campos, listas, detalhes
Exemplos"Arquivo salvo", "Deploy concluído", "Sincronizando…""Excluir conta?", "Confirmar pagamento", "Preencha os dados"
Regra de ouro: se o usuário precisa decidir algo ou se o erro bloqueia a continuação do fluxo, use Modal. Se é só confirmação de que algo aconteceu em segundo plano, use Toast.
