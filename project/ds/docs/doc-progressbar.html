Progress Bar doc

Barra que comunica progresso — determinado (valor 0–100), indeterminado (carregando) ou segmentado (etapas de um fluxo). Compartilha o OB_TONES com Alert e Toast para consistência de cor.

1 · Uso

Use para deixar o usuário ciente de quanto falta — upload, onboarding por etapas, cota de plano, progresso de tarefa longa.

Modos

  • Determinado — value 0–100 com atualização em tempo real.
  • Indeterminado — duração desconhecida; loop animado.
  • Segmentado — N passos discretos; os concluídos ficam coloridos.
✓ Faça

Mostre rótulo de porcentagem (showLabel) quando o valor é relevante para o usuário — upload, cota de armazenamento.

✕ Evite

Usar a barra indeterminada por mais de 8–10 s sem feedback; prefira um skeleton ou estado de loading mais descritivo.

Composição com outros componentes

  • Alert acima quando a cota atingiu o limite (tone="danger").
  • Toast com barra estreita (size sm) para uploads curtos.
  • CodeInput com barra segmentada para indicar etapa do fluxo 2FA.

3 · Guia de conteúdo

  • Rótulo de porcentagem: numérico e sufixado — "67%".
  • Label acima (em contexto de cota): "Armazenamento — 8,2 GB de 10 GB".
  • Segmentos: use Caption abaixo — "Etapa 2 de 4" ou nomes das etapas.
  • Evite repetir a porcentagem em texto se showLabel já a exibe.

4 · Guia de design

Tamanhos. sm = 6px (Toast, inline), md = 10px (padrão), lg = 14px (destaque, onboarding).

Tokens. Trilha --ob-bg-warm. Preenchimento na cor do tom (OB_TONES[tone].fg). Rótulo em --ob-font-mono peso 600.

Motion. Determinado: width com transição de 400ms cubic-bezier(.4,0,.2,1). Indeterminado: loop de 1,4s ease-in-out. Sem bounce.

Acessibilidade: use role="progressbar" com aria-valuenow, aria-valuemin="0" e aria-valuemax="100". Para indeterminado, omita aria-valuenow.
