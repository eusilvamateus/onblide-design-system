Layers

Escala oficial de z-index do Onblide Design System. Todo valor de z-index nos componentes deve referenciar um token desta escala — nunca um literal numérico.

0
Base
--ob-z-base fluxo normal de stacking
10
Raised
--ob-z-raised sidebar fixa · sticky header
100
Dropdown
--ob-z-dropdown FloatingPanel · Select · Datepicker popup
200
Tooltip
--ob-z-tooltip Tooltip (acima de dropdowns)
300
Overlay
--ob-z-overlay backdrop de Modal · backdrop de Drawer
400
Modal / Drawer
--ob-z-modal Modal panel · Drawer panel
500
Toast
--ob-z-toast Toast stack (acima de tudo interativo)
9000
System
--ob-z-system debug overlays · dev tools

Regras de uso

RegraDescrição
Nunca literais Nunca escreva z-index: 1200 ou zIndex: 9999 num componente. Sempre var(--ob-z-*).
Modal + Drawer Compartilham a mesma camada (--ob-z-modal). Nunca devem estar abertos simultaneamente — usar a mesma camada é intencional.
Dropdown dentro de Modal FloatingPanel dentro de um Modal usa --ob-z-dropdown — e funciona porque o stacking context do Modal já o isola. Não "bump" o z-index para compensar.
Toast sempre no topo --ob-z-toast (500) deve ser sempre a camada mais alta da UI interativa. Apenas overlays de sistema (debug, tweaks-panel) ficam acima — via --ob-z-system.
Deck-stage e DC runtime Usam valores próximos a INT_MAX deliberadamente (acima de qualquer app layer). Fora do escopo desta escala — não migrar.
z-index internos Valores de 1 ou 2 dentro de um componente (ex: thumb do Slider acima das marks) são relativos ao stacking context local. Não precisam de token semântico.
Adicionando uma nova camada: antes de criar um valor fora da escala, verifique se uma camada existente não serve. Se precisar de uma nova, adicione-a à escala em tokens.css e documente aqui — nunca use um literal sem registrá-lo primeiro.
