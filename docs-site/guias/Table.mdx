## Uso

Use Table para dados estruturados com 3+ colunas onde o usuário precisa escanear, comparar ou selecionar itens. Para listas simples de 1–2 atributos, prefira uma lista comum.

### Quando usar cada feature

- **Seleção** (`selectable`) — quando há ações em lote: excluir, exportar, mover selecionados.
- **Ordenação** (`sortable` por coluna) — quando a ordem importa para o usuário (data, valor, status). Sem `onSort`,
  a Table ordena as linhas sozinha ao clicar no cabeçalho (crescente → decrescente → sem ordenação), reconhecendo
  data em `dd/mm/aaaa`, número e texto. Use `onSort` só quando quem busca os dados precisa decidir a ordenação —
  paginação no servidor, por exemplo — caso em que a Table para de ordenar sozinha e só avisa qual coluna foi
  clicada.
- **Loading skeleton** (`loading`) — sempre que os dados vêm de requisição assíncrona.
- **Estado vazio** (`emptyState`) — nunca deixe a tabela simplesmente sem linhas; oriente o próximo passo.

### Composição

- **Tabs** acima para filtrar categoria de dados.
- **SearchInput** para filtro inline.
- **Badge** nas células de status/prioridade via prop `render`.
- **Pagination** abaixo para conjuntos grandes.
- **Dropdown** (kebab) por linha para ações contextuais.

## Formatação

```jsx
<Table
  columns={[
    { key: 'name',   label: 'Tarefa',  bold: true },
    { key: 'status', label: 'Status',  render: (v) => <Badge tone="green">{v}</Badge> },
    { key: 'due',    label: 'Prazo',   sortable: true, width: 90 },
  ]}
  rows={tasks}
  selectable
  loading={isLoading}
  emptyState="Nenhuma tarefa. Crie uma acima."
/>
```

Sem `onSort`, é só isso — clicar em "Prazo" já ordena. Com dados paginados no servidor, controle a ordenação você
mesmo:

```jsx
<Table
  columns={columns}
  rows={tasks}
  sort={sort}
  onSort={(key) => buscarPagina({ sort: proximaOrdenacao(sort, key) })}
/>
```

Tipo `Column`: `{ key, label, bold?, sortable?, width?, render?: (value, row) => ReactNode }`

## Guia de conteúdo

- Cabeçalhos: substantivos curtos. "Tarefa", "Status", "Prazo" — nunca verbos.
- Coluna de nome: sempre a primeira, em negrito, com o identificador principal do item.
- Status: use Badge com tom semântico (green=concluído, blue=andamento, orange=pendente, red=atrasado).
- Datas: formato "dd mmm" (ex: "04 jun") — compacto e legível.
- Estado vazio: inclua um CTA. "Nenhuma tarefa encontrada. Criar tarefa."
- Estado de loading: skeleton automático — não adicione texto.

## Guia de design

**Tokens.** Cabeçalho: mono 11px uppercase, cor `--ob-fg-mute`, borda de baixo `1px solid --ob-line-soft`, igual à das linhas (a hierarquia vem da tipografia; só o contorno externo usa `--ob-border`). Linha: 14px, hover `--ob-bg-warm`, selecionada `color-mix(--ob-blue 8%)`. Borda entre linhas `--ob-line-soft`.

**Scroll horizontal.** O container tem `overflow-x: auto` para não quebrar o layout em viewports estreitas. Em mobile (\< 640px), considere uma visualização alternativa em cards empilhados.

**Seleção.** Checkbox indeterminate quando parte das linhas está selecionada. Linha selecionada com background azul sutil. Ação em lote deve aparecer acima da tabela ao selecionar ≥ 1 linha.

<Nota>

**Table não é mobile-first.** Para viewports abaixo de 640px, converta os dados em cards verticais ou use um layout responsivo alternativo. Tabela com scroll horizontal é aceitável somente em contextos de uso desktop.

</Nota>
