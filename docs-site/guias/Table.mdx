## Uso

Use Table para dados estruturados com 3+ colunas onde o usuário precisa escanear, comparar ou selecionar itens. Para listas simples de 1–2 atributos, prefira uma lista comum.

### Quando usar cada recurso

- **Identificador da linha** (`rowKey`): a seleção e as linhas abertas seguem esse identificador, então continuam certas ao paginar, filtrar, ordenar ou excluir. Sem `rowKey`, a Table usa o campo `id` da linha e, na falta dele, a posição. Se as linhas mudam, tenha um `id` ou passe `rowKey`.
- **Seleção** (`selectable`): quando há ações em lote, como excluir, exportar ou mover selecionados. `onSelect` recebe as linhas selecionadas da página e todos os identificadores selecionados. Para selecionar entre páginas ou limpar a seleção depois de uma ação, controle com `selectedKeys`.
- **Ordenação** (`sortable` por coluna): quando a ordem importa para o usuário (data, valor, status). O cabeçalho vira um botão, que funciona com clique, Enter ou Espaço e anuncia a ordem atual a leitores de tela. Sem `onSort`, a Table ordena as linhas sozinha (crescente → decrescente → sem ordenação), reconhecendo data em `dd/mm/aaaa`, número e texto. Use `onSort` só quando quem busca os dados decide a ordenação, como numa paginação no servidor; nesse caso a Table só avisa qual coluna foi clicada.
- **Linha clicável** (`onRowClick`): quando a linha leva ao detalhe do item. A linha recebe foco e abre com Enter ou Espaço. Cliques em botões, links, checkboxes e campos dentro da linha não disparam `onRowClick`.
- **Linha expansível** (`renderExpanded`): para mostrar detalhes abaixo da linha sem sair da tela, como itens de um pedido ou o histórico de um registro. Linhas para as quais a função devolve `null` não ganham o botão de abrir. Controle com `expandedKeys` e `onExpandedChange`, ou use `defaultExpandedKeys`.
- **Cabeçalho fixo** (`maxHeight`): em listas longas sem paginação, limite a altura; o corpo rola e o cabeçalho fica no topo.
- **Colunas numéricas** (`numeric` na coluna): valores, quantidades e totais ficam à direita e em JetBrains Mono, em que todos os algarismos têm a mesma largura, para que as casas fiquem uma embaixo da outra. A Poppins não tem algarismos de largura fixa. Para só mudar o alinhamento, use `align`.
- **Título** (`caption`): um título visível acima do cabeçalho, também lido por leitores de tela. Sem título visível, nomeie a tabela com `ariaLabel`.
- **Carregamento** (`loading`): sempre que os dados vêm de requisição assíncrona. As linhas viram **Skeleton**.
- **Estado vazio** (`emptyState`): nunca deixe a tabela simplesmente sem linhas, oriente o próximo passo. Passe um **EmptyState** com `size="sm"`.

### Tamanhos

`size` aceita `sm`, `md` (padrão) e `lg`, com texto de 13, 14 e 15px e o espaço das células crescendo junto. Use `sm` em painéis densos e telas de consulta, e `lg` em tabelas curtas que são o centro da página.

### Composição

- **Tabs** acima para filtrar categoria de dados.
- **SearchInput** para filtro inline.
- **Badge** nas células de status/prioridade via prop `render`.
- **Pagination** abaixo para conjuntos grandes; com `selectedKeys`, a seleção sobrevive à troca de página.
- **Menu** (kebab) por linha para ações contextuais.

## Formatação

```jsx
<Table
  rowKey="id"
  columns={[
    { key: 'name',   label: 'Tarefa',  bold: true },
    { key: 'status', label: 'Status',  render: (v) => <Badge tone="success">{v}</Badge> },
    { key: 'due',    label: 'Prazo',   sortable: true, width: 90 },
    { key: 'hours',  label: 'Horas',   numeric: true },
  ]}
  rows={tasks}
  selectable
  loading={isLoading}
  emptyState="Nenhuma tarefa. Crie uma acima."
/>
```

Sem `onSort`, é só isso: clicar em "Prazo" já ordena. Com dados paginados no servidor, controle a ordenação e a seleção você
mesmo:

```jsx
<Table
  rowKey="id"
  columns={columns}
  rows={tasks}
  sort={sort}
  onSort={(key) => buscarPagina({ sort: proximaOrdenacao(sort, key) })}
  selectable
  selectedKeys={selecionadas}
  onSelect={(_, chaves) => setSelecionadas(chaves)}
/>
```

Tipo `TableColumn`: `{ key, label, bold?, sortable?, align?, numeric?, width?, render?: (value, row) => ReactNode }`

## Guia de conteúdo

- Cabeçalhos: substantivos curtos. "Tarefa", "Status", "Prazo", nunca verbos.
- Coluna de nome: sempre a primeira, em negrito, com o identificador principal do item.
- Status: use Badge com tom semântico (green=concluído, blue=andamento, orange=pendente, red=atrasado).
- Datas: formato "dd mmm" (ex: "04 jun"), compacto e legível.
- Valores: com a unidade ou a moeda, em coluna `numeric`.
- Título (`caption`): diga o que a tabela lista, como "Pedidos de outubro".
- Estado vazio: inclua um CTA. "Nenhuma tarefa encontrada. Criar tarefa."
- Estado de loading: skeleton automático, não adicione texto.

## Guia de design

**Tokens.** Cabeçalho: JetBrains Mono `--ob-fs-12` (`--ob-fs-13` no `lg`), peso `--ob-w-medium`, sem caixa-alta, cor `--ob-fg-soft`, borda de baixo `1px solid --ob-line-soft`, igual à das linhas (a hierarquia vem da tipografia; só o contorno externo usa `--ob-border`). Linha: `--ob-fs-14` no `md`, hover `--ob-bg-warm`, selecionada `--ob-blue-100`. Detalhe expandido sobre `--ob-bg-alt`. Foco do teclado no cabeçalho e na linha clicável com `--ob-focus-ring`.

**Movimento.** A linha expandida abre e fecha deslizando (`--ob-dur-base`), e a seta do botão gira junto. Com movimento reduzido, a troca é imediata.

**Scroll.** O container rola na horizontal pelo `ScrollArea`, para não quebrar o layout em telas estreitas. Com `maxHeight`, rola também na vertical, com o cabeçalho fixo.

**Seleção.** Checkbox indeterminate quando parte das linhas da página está selecionada. Linha selecionada com fundo azul sutil. A ação em lote aparece acima da tabela ao selecionar ≥ 1 linha, com o total selecionado e um botão para limpar.

<Nota>

**Table não é mobile-first.** Abaixo de `sm` (768px), converta os dados em cards verticais ou use um layout alternativo. Tabela com scroll horizontal é aceitável somente em contextos de uso desktop.

</Nota>
